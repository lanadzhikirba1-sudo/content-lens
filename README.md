# content lens

Сайт аналитики Instagram по макету `content-lens-demo.html`. Данные профиля и публикаций собирает Apify.

## Что внутри
- **Вход**: email → 6-значный код (SMTP) → выбор Instagram (ник или ссылка).
- **Обзор**: профиль, KPI за период против прошлого периода, график (подписчики, просмотры Reels/видео, лайки, комментарии, публикации, ER) с периодами 7/30/90 дней и своими датами, шагом дни/недели/месяцы, режимом «Сравнить динамику», топ публикаций, сводка по форматам.
- **Контент**: календарь по месяцам и список с поиском; на каждой публикации — комментарии, просмотры, лайки, ER; попапы с текстом и медиа (фото, видео, карусели).
- **Публикация**: метрики, редактируемые тема / хук / CTA (сохраняются на сервере), последние комментарии.
- **Ещё**: статус подключения, ручное обновление, смена аккаунта, выход.

## Откуда данные
| Что | Actor Apify |
|---|---|
| Профиль: подписчики, подписки, био, аватар | `apify/instagram-profile-scraper` |
| Публикации за 6 мес.: подпись, лайки, комментарии, просмотры, медиа | `apify/instagram-scraper` (resultsType=posts) |

Первый сбор — до `POSTS_LIMIT` постов за `FIRST_SYNC_MONTHS`. Дальше раз в сутки сервер перечитывает профиль и посты за последние 30 дней — это обновляет метрики свежих постов и копит **историю подписчиков** (Apify отдаёт только текущее число, поэтому график подписчиков растёт со дня подключения).

**Недоступно в открытых данных** (в интерфейсе честно «—» или убрано): охват, сохранения, репосты/отправки, посещения профиля, Stories, продажи. Для них нужен Instagram Graph API от владельца аккаунта.

Ссылки на медиа Instagram живут несколько дней — сервер проксирует их (`/api/media`); если ссылка устарела, нажмите «Обновить данные».

Ориентир по стоимости Apify: первый сбор ~150 постов ≈ $0,35; ежедневное обновление ≈ $0,05–0,15 на аккаунт.

## Запуск
```bash
npm install
cp .env.example .env   # заполнить APIFY_TOKEN
node --env-file=.env server.js        # http://localhost:3000
npm run dev                            # тестовые данные без Apify
```
Node 20+.

## Деплой (Railway / Render / любой VPS)
1. Залить папку в репозиторий, создать сервис — старт `npm start`.
2. Переменные: `APIFY_TOKEN`, `SMTP_*`, `ALLOWED_EMAILS`, `SESSION_SECRET`, `NODE_ENV=production`.
3. Подключить volume и указать `DATA_DIR` на него — иначе история подписчиков сотрётся при редеплое.

⚠️ Без SMTP код входа показывается на экране — любой сможет войти и тратить ваши кредиты Apify. В проде обязательно задайте SMTP и/или `ALLOWED_EMAILS`.

## Структура
```
server.js          API, сессии, синхронизация, прокси медиа, автообновление
lib/apify.js       запуск акторов Apify (run → poll → dataset)
lib/transform.js   нормализация ответа Apify
lib/store.js       хранилище в JSON-файле
lib/mailer.js      отправка кода
lib/mock.js        тестовые данные в формате Apify
public/            интерфейс (base.css — стили из демо, app.css, app.js)
```

## Текущий деплой (Railway Function)
Сайт: https://content-lens-production-c6d7.up.railway.app — устанавливается как приложение (PWA).

Railway Functions принимают один файл до 96 КБ, поэтому:
- `railway/loader.ts` — код функции: держит `/__upload` и проксирует запросы в приложение;
- приложение собирается в один файл `app.mjs` (`node railway/build.mjs`, внутри — сжатые ассеты) и хранится на volume `/data`;
- новая версия загружается на `https://…/__upload` с токеном `UPLOAD_TOKEN` (он в переменных сервиса на Railway).

## Подключение клиентов (полная статистика)
Клиент открывает ссылку-приглашение, входит в свой Instagram на сайте Instagram и разрешает доступ на чтение статистики. Пароль клиента сайт не видит. Токен Instagram действует 60 дней, продлевается автоматически и хранится зашифрованным (AES-256-GCM).

Собирается: профиль, публикации с охватом/просмотрами/сохранениями/репостами/посещениями профиля, Stories (каждый час, пока живы 24 ч), охват аккаунта и новые подписчики по дням.

### Настройка приложения Meta (один раз)
1. developers.facebook.com → My Apps → Create App → тип **Business**.
2. Добавить продукт **Instagram** → «API setup with Instagram login».
3. В «Business login settings» → OAuth redirect URI: `https://content-lens-production-c6d7.up.railway.app/auth/instagram/callback`.
4. Скопировать **Instagram App ID** и **Instagram App Secret** → переменные Railway `IG_APP_ID`, `IG_APP_SECRET`.
5. App settings → Basic: Privacy Policy URL `…/privacy`, User data deletion `…/data-deletion`.
6. Пока приложение в режиме разработки, подключаться могут только Instagram-аккаунты, добавленные в App Roles → Instagram Testers (клиент принимает приглашение в Instagram: Настройки → Приложения и сайты → Приглашения тестировщика). Для любых клиентов без этого шага — App Review на `instagram_business_basic` и `instagram_business_manage_insights` (Advanced Access) и Business Verification.

Тестовый режим без Meta: `IG_MOCK=1`.

### Обновление кода на Railway Function
`node railway/build.mjs` собирает `railway/dist/app.mjs` (папка в git не попадает). `express` и `nodemailer` бандл берёт у лоадера через `globalThis` (`railway/shims/`), поэтому npm-импортов в нём нет.
Загрузить: открыть `/__upload`, ввести `UPLOAD_TOKEN` и выбрать файл — или временно задать `UPLOAD_OPEN_UNTIL` = время в мс, до которого загрузка открыта без токена (максимум час).

## Аудит профиля (связка с ig-audit)
- `GET /api/audit/export?handle=…` — данные аккаунта по контракту `Marketing/ig-audit/CONTRACT.md` (под сессией).
- `PUT /api/audit/report/:handle` — приём готового HTML-отчёта, заголовок `x-audit-token` = `AUDIT_UPLOAD_TOKEN`; без переменной приём закрыт.
- `GET /audit/:handle` — показ отчёта (под сессией).

## Тестовые данные
Аккаунты и подключения, собранные с `APIFY_MOCK=1` / `IG_MOCK=1`, удаляются при старте в боевом режиме — пользователи возвращаются к выбору аккаунта.
